# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | Repro report's environment record; repo-facts block (what the bug template asks for) | The report states the environment a stranger needs to place the attempt: OS, the tool's version, and any setting the issue says changes the outcome (driver, shell, build profile). A terse one-line environment that covers these passes. A report with no environment record, or one that omits a setting the issue says matters, fails. | required |
| steps-rerunnable | Repro report's steps and commands | A stranger could run the steps as written: the commands are shown, and each input is either shown, taken verbatim from the issue body, or described precisely enough to recreate (what it contains and which part triggers the behavior). A small input described in words that pin down the trigger passes; do not fail a step only because a file's contents are not pasted in full. Fails if the reproduction depends on a private file, repo, or config the reader cannot get, or if the step that triggers the behavior is missing or skipped. | required |
| shows-issue-behavior | Artifacts (output, logs, transcripts) read against the behavior the issue body describes | The shown output is the behavior the issue reports (same error, exit code, or symptom), not an adjacent one: a graceful error where the issue reports a crash, a different error caused by a modified input, output that only proves the tool runs, or a different symptom. For an honest cannot-reproduce, the artifact shows a real attempt and what it produced instead. | required |
| faithful-target | Report's environment and versions against the issue body and thread highlights (confirmed versions, maintainer trigger notes) | The version and setup tested match what the issue reports, or the report states and explains each deviation (older version, different OS, changed input) and does not present the result as evidence about the reported bug. | required |
| honest-outcome | Claims in both comments against the artifacts shown | Every claim (reproduced, cannot reproduce, root cause, "guaranteed reproducible") is backed by an artifact the comment shows. A cause is stated as a hypothesis unless evidence supports it. An evidenced cannot-reproduce passes. A confident claim with no artifact, or a claim that exceeds what the artifact shows, fails. | required |
| claim-specific | Claim comment against the issue | Names this issue's own specifics (the command, function, or behavior) and promises only an investigation and a report: no fix promised, no date, no guarantee. A generic assign-me, a +1, or a comment that could be pasted on any issue fails. | required |
| repo-conventions | Repo-facts block: stated contribution and AI-use policy; both comments | The comments follow the repo's stated rules. If the policy requires disclosing AI assistance, the comments must disclose it; treat course packages as AI-assisted work for this rule only, so a comment with no disclosure fails. If the policy requires comments to be written by a human in their own words, a comment in a first-person human voice with its own specifics passes; do not assume AI authorship for this rule, and fail only a comment that reads as generic or templated. If the policy is permissive, silent, or only asks the author to understand and take responsibility for the work, this passes. A comment that breaks a stated rule fails. | required |
| next-step-concrete | Last lines of the repro report | States a concrete next step (for example, a failing test to write or a code location to investigate). | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Preferred checks never change the verdict. Treat unclear as fail.
